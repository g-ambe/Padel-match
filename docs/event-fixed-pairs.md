# 一部ペア固定・戦績反映の実装報告

基準：main `7c472d1255cb47105b9ffa80ffbd8efe36a264b6`。対象はグループの自動フレンドリーマッチ。Draftでレビューし、今回の作業では本番SQL・マージ・デプロイを行わない。

## 1. 保存方式

0040 Migrationで3表を追加する。`event_fixed_pairs` は現在の固定、`event_fixed_pair_state` はイベントの版数・実使用済みの印・設定保存の再試行、`event_fixed_pair_rounds` は生成要求・当時の参加可能者・出場者・実際に組んだ固定ペア・5人で分かれたペアを保持する。

参加者IDは選手プロフィールIDではなく `event_participants.id`。イベントIDを含む複合外部キーと、イベント行ロック下の重複検査で別イベント参照・2列をまたぐ重複固定を拒否する。既存の参加者・試合・スコア・プロフィールはMigrationで更新しない。

## 2. UI

参加者カードに固定組数・通常参加者数・🔒付きペア一覧・解除・追加・再取得を追加。追加ダイアログでは生成対象の未固定者から2人を選ぶ。既存GuestNameを再利用し、同じ人・固定済みの人は候補から除外する。主なボタンは44px以上。保存完了は版数と返却されたペア全体を検査して表示し、不明応答・競合・0件を成功扱いしない。

設定はDBから復元し、生成前にも再取得する。旧画面で固定条件を迂回する操作は拒否されるため、リリース後は古いタブも再読み込みする。端末内では生成・設定保存・面数保存・削除を排他制御。別端末ではDBトランザクションをイベント行で直列化し、計算中に設定が変わった場合は版数不一致で保存を停止する。ブラウザで計算している時間全体を、他端末の操作禁止期間にはしない。

## 3. 4人

新規固定不可。既存設定は削除せず一時停止し、元の生成器をそのまま使う。5人以上に戻ると適用を再開する。参加可能な片方しかいない設定も、4人時は一時停止することを表示する。

## 4. 5人

設定時・一覧に指定の警告を表示する。休憩は個人単位で探索し、休憩回数差・連続休憩・回数の偏りを小さくしたうえで固定分割を減らす。公平性が同じなら2組とも維持できる配置を優先する。片方の自動休憩時だけ残る人を未固定者として組み、そのRound後も設定を保持する。

1組・2組固定とも50Round×3モードで、各人10回休憩、連続休憩なし、元のペアへの復帰を確認する。明示的なresting/absentはこの例外に含めない。

## 5. 6人以上

固定2人を同じ出場・休憩単位とし、未固定者を1人単位で休憩候補を探索する。全員が同じ休憩率を持てる構成かを最初に検査する。成立しない構成を未固定者の休憩固定化で埋めない。

例：9人・2面で固定1組以上、13人・3面で固定1組以上、17人・4面で固定1組以上では休憩枠が1人のため、その固定ペアに休憩を回せない。11人・2面・固定4組＋未固定3人、7人・1面・固定3組＋未固定1人も公平性が成立しない。面数減・固定解除・人数調整を案内し、5人例外を拡大しない。

## 6. 生成モード

`lib/friendly-rounds.ts` は変更しない。固定0組では元の生成器へそのまま渡し、結果・乱数消費を完全一致させる。固定ありだけ追加生成器で制約内を探索する。4人でも元の生成器へ直接渡す。

バランス評価は既存の当日80%＋同グループ過去20%を再利用し、ゲストは当日評価。10試合解放条件・得点0・引き分けを維持し、DBでも解放条件を再確認する。ライバル対決は既存の好調者評価を利用する。選択モードの保存方式は変更しない。

## 7. 未固定者

休憩枠を確定してから固定チームを取り置き、残りの選手をビットマスクDPで編成する。通常は過去ペア・対戦重複、バランスは強弱ペアとチーム戦力差、ライバルは好調者同士の対戦を評価する。生成後の単純な選手入れ替えは行わない。

連続同一ペアの例外は登録済み固定ペアだけ。例えば8人・2面で固定3組、未固定2人が直前にもペアだった場合、未固定ペアを変える余地がないため停止する。これを許容する仕様変更は今回行わない。

## 8. 欠席・途中変更

片方だけ明示休み・欠席・退会等で生成対象外の場合、5人以上では状態を案内して停止する。両方とも対象外なら設定を残して無視する。途中追加・退出・面数変更は次Roundで最新状態を再検査し、既存Roundは変更しない。

新しい監査には当時の参加可能者と出場者を保存し、その差だけを自動休憩として数える。**適用前のRoundには当時の欠席・明示休みを区別する記録がないため、固定ありの休憩計算では、その古いRoundを自動休憩と推測して加算しない。** ペア・対戦・当日戦績は従来どおり全履歴を使う。適用後のグループ自動生成は固定0組でも監査するので、途中で固定した際も新しい個人休憩履歴を継続できる。

## 9. 戦績の切替

固定が実際に同じチームで生成されたときだけ `used_fixed_pairs=true` とし、活動中のstats_modeをundecidedにする。設定だけ・4人一時停止・5人の分割だけでは使用済みにしない。一度trueになると、固定全解除・Round削除でも戻さない。

使用済みイベント終了時は「このイベント内だけに保存」または「グループ通算戦績に反映」を未選択で表示する。選択なしでは確定できず、DBでも拒否する。再開時はundecidedへ戻し、再終了時に選び直す。使用しない自動イベントはofficial、手動イベントは従来の選択を維持する。

## 10. 既存ランキング

個人・ペア・グループの計算式、ゲスト対象条件、70/20/10ランキング、共有、当日ランキング・MVPは変更しない。既存の「closedかつofficialかつ未削除」の履歴取得条件で反映・除外される。バランスの将来評価も同じ既存条件を利用する。保存済み集計への累計加算は行わない。

## 11. RLS・権限

[現行メタデータ確認記録](../supabase/maintenance/event-fixed-pairs/preflight-review.md)のとおり、利用者提供の最新RLS・ACL・トリガーを確認した。旧profile_id所属・選手プロフィール所属・super_userを既存方式で判定し、新機能にはログインと対象グループを追加確認する。手動・チーム・グループなし・削除済みは対象外。

新3表はRLSを有効化し、同グループの有効メンバーまたはsuper_userだけSELECT可能。匿名・別グループは取得できない。直接DMLは禁止し、認証限定のRPCで保存・生成・終了を行う。SECURITY DEFINERは空search_path、明示スコープ、実行権限の限定を行う。旧クライアントの直接生成・終了・編成更新で固定条件を迂回する経路には追加ガードを設ける。スコア・動画・削除の既存操作は保持する。

生成・設定・終了はREAD COMMITTED限定。イベント行・参加者行ロック、版数、最新Round・面数・対象者の比較で競合を停止する。生成要求ID＋本文を保存し、同じ要求の再送は同じRoundを返す。異なる本文での再利用・削除済みRoundの再生成は拒否する。結果不明の要求はアカウント・イベントごとのsessionStorageにも保持し、画面再読み込み後に確認できる。
