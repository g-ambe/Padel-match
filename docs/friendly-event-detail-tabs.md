# 通常フレンドリー開催詳細の3タブ

対象は `/events/[id]` の組み合わせ戦（自動・手動、ログイン・ゲスト、グループあり・なし）。チーム戦・オフィシャル詳細は対象外。

## 配置

| 配置 | 既存機能 |
| --- | --- |
| 共通 | 開催名・編集、開催状態、ゲスト案内、成功・エラー、保存中・未保存スコア、参加状態更新の失敗・再取得、既存TOP操作 |
| 対戦 | マッチボード、スコア入力・編集・自動保存・取消・再試行、履歴拡大、生成モード、コート数、固定ペア、手動Round作成・編成編集、試合YouTube、開催動画一覧・管理、下部のイベント終了 |
| 参加者 | 一覧、参加・手動休憩のワンタップ、変更メニューの欠席・復帰、ゲスト名編集、イベント限定ゲスト追加 |
| 結果 | 開催中の暫定結果・既存勝率ランキング、結果サマリー（勝利数・勝率・得失点差・MVP）、戦績反映状態、終了後の共有・再開・権限に応じた削除 |

取得した開催状態が開催中なら対戦、終了済みなら結果を初期表示する。同一開催の再取得で選択タブを戻さない。終了成功で結果、再開成功で対戦へ切り替える。DB更新拒否・0件では切り替えない。終了後も他タブを閲覧できる。

## 入力と保存

- タブパネルは `hidden` による表示切替のみで、マウントを維持する。スコアポップアップ、YouTubeの入力・折りたたみ、開催動画フォーム、手動Round・編成編集、固定ペア設定のローカル状態を破棄しない。
- タブ切替では `loadAll`・保存処理を呼ばない。ScoreSaveProviderと保存キューは変更しない。
- 数字選択、自動保存、保存済み結果の編集確定・取消、履歴モーダルは従来のコンポーネントを再利用する。ポップアップや確認画面を開いたまま背景のタブを切り替える操作は制限する。
- 保存中・保存失敗の件数をタブ共通で表示し、対戦の既存再試行操作へ戻れるようにする。既存の下部ナビ集中モード・離脱ガード・セーフエリアを維持する。
- 通常ナビゲーションの移動と、ゲストを削除する既存の明示的な `TOPへ戻る` は区別する。今回ゲストの保存・削除方法は変更しない。

## 参加状態

`active` ↔ `resting` は休憩ボタン1回で更新する。`absent` へは「変更」→「欠席にする」、欠席からの復帰は「変更」→「参加で復帰」または「休憩で復帰」。欠席者には休憩ボタンを出さない。参加者削除は追加しない。

既存の `event_participants.status` 更新を使い、イベントID・参加者ID・表示上の変更前状態を指定する。返却1行を検査し、保存後に再取得して状態を照合する。成功前には表示を切り替えない。同じ人への送信ロック、エラー、確認用の再取得を設ける。確認失敗ではDB上の保存が成功している可能性があるため、自動で元に戻さず状態の再取得を案内する。

既存の開催操作権限とDBのRLSは維持する。参加状態の保存中は生成・固定設定保存・終了等の開始ボタンを止める。作成済みの対戦・スコア・固定ペアは書き換えない。スコア保存に伴う遅い再取得で新しい参加状態を上書きしないよう、状態更新のリビジョンを確認する。

自動休憩は参加状態とは別に表示する。既存のRound参加可能者記録がある場合だけ「直近Round N の自動休憩」とする。記録のない過去・ゲスト・グループなしのRoundは「出場なし（当時の参加状態は未記録）」とし、自動休憩だったと推測しない。新しいDB項目やゲスト保存項目は追加しない。

## 検証方法

```bash
npm test
npx tsc --noEmit --incremental false
WRANGLER_LOG_PATH=/tmp/padel-event-tabs-wrangler.log \
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 \
NEXT_PUBLIC_SUPABASE_ANON_KEY=local-test-key npm run cf
npm run start -- --hostname 127.0.0.1 --port 3002
# 別のターミナル。Playwright・Chromiumを利用する。
node tests/browser/event-detail-tabs.cjs
node tests/browser/event-fixed-pairs.cjs
node tests/browser/match-navigation.cjs
node tests/browser/group-navigation-return.cjs
```

ビルドとブラウザ試験は順に実行する。ブラウザ試験では架空データとローカル応答を使う。固定ペアの試験は既存の隔離PostgreSQL互換環境でRPC・権限を検証するもので、本番SQLを実行しない。

320・375・390pxと両テーマを対象とする。実機iPhone/Safari、本番ログイン・本番データへの書込みは対象外。DB・Migration・RLS・RPCの変更、手動SQL、本番デプロイ、マージは不要かつ未実施。
