# フレンドリーチーム戦のUIとグループ候補

作成画面は所属（一般メンバーを含む）と公開グループを候補にする。
`readTeamGroups` は認証・プロフィール・新旧所属参照・グループ取得のエラーを伝播する。
候補は既存RLSで読めた有効グループから絞り込み、IDで重複排除する。
取得失敗時は作成できない。公開グループの選択で所属・管理権限は付与されない。

A/Bの実際の関連グループは `event_team_sides.club_id` へ独立して保存する。
`events.club_id` は選択された本人所属グループを優先し、どちらにも所属しない場合はNULLにする。
公開の相手を選んだだけで、その所属として開催をINSERTしない（既存events_insert条件を維持）。
所属なしの作成者自身の開催は、既存の作成者権限で管理する。

チーム名はグループ選択時の初期値のみ追従する。手動編集フラグはA/B別。
グループ新規作成への一時退避にもフラグを保存する。保存済みチーム名をグループ名へ同期しない。

詳細画面の対戦・チーム・結果パネルはhiddenで保持する。
TeamMatchCardsは同じPortalコンテナを一覧・全件ダイアログの間で移し、再マウントしない。
既存カード編集ではScoreInputを追加せず、既存の入力から編集フォームの保存処理を呼ぶ。
スコアの送信関数・保存キュー・集計・0–0除外・勝点は変更しない。
結果のチーム・個人・ペア戦績は終了後のみ。開催管理には既存の終了・再開・削除・反映選択を残す。

DB・RLS・RPC・Migration・本番SQLの変更なし。
検証: npm test / tsc --noEmit / npm run cf:build / tests/browser/friendly-team-ui.cjs。
ブラウザ試験はローカル合成データのみを使用し、本番通信を遮断する。
