# グループ管理の削除ボタン修正

## 問題

通常のグループ管理で「グループ削除」を押しても、confirmGroupDeleteをtrueにするだけで、その状態を使う確認ダイアログが描画されていなかった。doDeleteGroupを呼ぶボタンもなく、削除要求が送信されない実装だった。
ユーザー報告は「エラーなし、グループ管理者で削除できない」。確認ダイアログ欠落と整合するが、ユーザーのブラウザ通信自体は取得していない。

加えて、ハンドラーは権限判定で関数そのものを参照し、DBエラー・0行更新を確認せず成功扱いにしていた。
RLSの物理DELETE禁止を解除しても、これらの画面不具合は解消しない。

## 修正後の操作

1. メイン管理者/スーパー管理者が「グループ削除」を押すと確認画面が開く。
2. 内容確認にチェックを入れるまで実行ボタンは無効。
3. 「削除する」でclubs.is_active=falseへ更新。物理DELETEは使わない。
4. 更新したidが一致する1行を確認してからグループ一覧へ移動する。
5. 権限拒否・0行更新・通信失敗は確認画面にエラーを表示し、成功扱いにしない。処理中の二重送信も防ぐ。

キャンセルはデータを変更しない。既存の共通AppDialogを使用する。
グループと関連する試合データは残る。今回RLS・RPC・本番データは変更していない。

## 検証対象

tests/group-delete.test.cjsで、確認UIの接続、未確認/権限不足/処理中の送信抑制、論理削除成功、失敗/0件/対象不一致、通信例外、二重送信を検証する。
本番の試験削除は行わない。アプリの本番反映後、ユーザーが不要な確認用グループを削除し、一覧から消えることを確認する。
SQL切り戻しは不要。アプリの当修正を戻せば修正前へ戻るが、今回の「削除できない」状態も戻る。

## 検証結果

- 追加6テスト成功、TypeScript noEmit成功、Next.js本番ビルド成功。
- 全体テストは163件成功、既存player-profile-repair.test.cjsがSQLのLF固定正規表現とWindows CRLFの不一致で初期化時に失敗。この修正による変更対象ではない。
- 本番ブラウザの実削除は未実施。RLS・本番データを変更していない。
