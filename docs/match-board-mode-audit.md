## 好調度の検算

対象イベントの成立済み・完了済み・0以上の整数スコアの試合だけを使用する。4選手が既知で重複せず、A／Bが各2人の試合が対象。スコア差から勝ち・引き分けを数え、試合数をnとして以下を使う。

`clamp(100 × (勝数 + 0.5 × 引分数 + 2) / (n + 4) + 2 × clamp(得失点差 / n, -4, 4), 0, 100)`

未出場は50。プロフィールのレベルや、グループランキングの70／20／10とは別の生成用指標である。個別に検算した10人全員が既存関数と一致した。

## 評価の優先順位と修正判断

1. 既存の600回探索で休憩者を選ぶ。モードや好調度には依存しない。
2. 700回のシャッフルでコート分割候補を探し、連続ペア数を最小化する。
3. ペアペナルティが最良値＋400以内の候補だけを評価する。ペア履歴は1回につき800、未経験相手がいるのに再登場する場合は4000等の強い条件がある。
4. 残った候補で `対戦重複ペナルティ + 0.6 × モード固有ペナルティ + 0以上5未満の乱数` を比較する。

代表seed1・24では、35コート分割を得た後の評価候補は3件だった。強いペア制約と対戦重複評価のため、モードを変えてもペア集合が同じになりやすい。UIの選択は生成器へ正しく渡され、解放条件・選択保持・休憩・ゲスト混在も既存回帰テストで確認した。1〜5面を指定しても参加人数の上限を守り、設定値自体を人数不足で書き換えない。

明確な生成実装不具合は確認していない。重み・生成ルール・解放条件・保持方法の修正は行っていない。バランスによるペア構成の変化を強める場合は、ペア再登場をどこまで許容するか、対戦相手の重複回避とどちらを優先するかの仕様判断が必要。係数変更は別の比較検証と合意を前提にする。
