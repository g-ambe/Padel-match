基準main：`ba4f6cf121c3dbc35b51bfda6eae680ee00da07d`（PR #164）。

**本番反映は保留。** 利用者が共有した現行RLS情報で、`dev_all_events` の無条件ALL許可が認証ユーザーに適用されることを確認した。画面の管理者判定だけでは他イベントへの直接更新を防げず、今回の権限要件を満たせない。依頼の「RLS変更が必要ならマージ停止」に従い、Draft PRでレビューできる状態まで仕上げ、マージ・デプロイ・DB／RLS変更は行わない。

## 名称・削除確認

- 通常、フレンドリーチーム、オフィシャルの試合一覧・入力エリアを「マッチボード」に統一。ランキングの「戦績」「結果サマリー」、試合種別、Round生成名は維持する。全件表示は「全試合履歴」のまま。
- 通常の削除確認は固定配置のdivだった。一方、全件履歴は `dialog.showModal()` のトップレイヤーを使うため、z-indexを増やしても確認が背面に隠れる構造だった。
- 確認も共通の `AppDialog` に変更。背景の履歴を残し、取消・×・背景・Escapeは確認だけを閉じる。確定時だけ従来の削除処理を呼ぶ。
- 確認開始時にカードを横へ強制移動する処理をやめた。スワイプによる削除申請自体は維持し、確認中はカードを通常位置へ戻す。
- `AppDialog` はレイアウト処理で開閉し、元のスクロール要素の位置を記録・復元する。削除成功後は両一覧の更新を待って確認を閉じ、消えたボタンへフォーカスを戻す問題を防ぐ。送信中の連打・閉じる操作も防ぐ。
- チーム・公式は既存のブラウザ標準確認を使用しており、全件履歴からの取消・確定が動くことを確認した。保存・削除ルールは変更しない。

## 利用コート数

自動生成イベントの次Round生成ボタンの横に、現在の「利用コート数／N面」を表示する。変更権限がある場合だけタップ可能にし、1〜5面の選択ダイアログを開く。数字は44px以上の操作領域を保つ。手動イベントに設定変更UIは追加しない。

設定を開く際に現在値を読み、保存時は次の条件で `events.court_count` だけを更新する。

- 対象イベントIDが一致
- 開催中、自動生成、未削除
- 開くときに確認したコート数と一致
- 入力は1〜5の整数

DBから更新対象1行と指定した面数が返った場合だけ画面の確定値を更新する。エラー・0行・競合では旧表示と選択入力を残し、成功と表示しない。別端末の変更を検出した場合は、現在値を確認して再操作するよう案内する。

設定はDBに保存するため、再読込・別端末から取得できる。設定を開くとき、ウィンドウのフォーカス復帰・表示復帰、生成開始時に最新値を読む。常時リアルタイム配信は追加しない。

生成処理は従来からDBの最新 `court_count` を生成器に渡していた。この仕様を維持し、画面表示にも反映する。各Roundの生成開始時に読んだ値を、そのRound全体のスナップショットとして使う。途中で別端末が変更しても生成中の試合へ面数を混在させず、その後の生成で新しい設定を読む。

同じ画面ではコート保存・Round生成・削除を同期ロックで競合させず、終了処理との重なりも防ぐ。端末間の完全な直列化やDBトランザクション化は追加しない。

人数不足の上限は既存どおり `min(設定面数, floor(アクティブ人数/4))`。例えば10人で5面を選んでも生成は2面にとどめ、保存した設定5面は書き換えず警告を出す。過去のRound・コート番号・得点・組み合わせは更新しない。

ゲストの自動生成イベントは既存のタブ内一時保存に `court_count` を保存し、DBへ書き込まない。再読込時の保持は同じタブ内のみで、別端末共有は対象外。

## 現行RLSによるマージ停止

利用者が提供した確認結果：

| 項目 | 結果 |
| --- | --- |
| eventsのRLS | 有効 |
| anonのcourt_count更新権限 | なし |
| authenticatedのcourt_count更新権限 | あり |
| dev_all_events | PERMISSIVE、ALL、anon／authenticated、USING true、WITH CHECK true |
| その他のeventsポリシー | 共有SELECT、作成者／グループ管理者UPDATE、super_user等。いずれもPERMISSIVE |

PERMISSIVEポリシーはORで評価される。認証ユーザーはSQL権限と無条件ALLポリシーの両方を持ち、役職別UPDATE条件だけでは制限されない。匿名ユーザーは更新権限がないため、匿名更新まで可能と判断してはいけない。

本実装はUI判定と既存RLSに従って送信するが、現在のRLSを安全な状態へ変える機能は含まない。モックで「権限なしのUI」「RLS拒否時に成功扱いしない」を確認しても、本番の更新権限が正しい証拠にはならない。

必要な対応は、既存の無条件ALL許可を整理し、作成者・管理者等の意図したUPDATE条件が実際に効く状態へ変更すること。ただしALL許可の整理はSELECT・INSERT・DELETEにも影響するため、共有・作成・通常／チームの管理操作を含む影響確認が必要。今回はRLS・GRANT変更が禁止されており、修正SQLやマイグレーションは追加・適用していない。

[確認用SELECT](match-board-events-permissions.sql) は読み取りだけで、こちらから本番へ実行していない。公開APIでは管理カタログ取得がPGRST106で拒否されたため、現行ポリシーの確認は利用者提供結果に基づく。
