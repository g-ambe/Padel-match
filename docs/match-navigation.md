# 共通ナビゲーション・試合トップ（PR①）

## 画面と遷移

- ログイン後の `/home` を試合トップとして使用する。
- 表示対象は初期値「すべての閲覧可能な試合」、個別グループ、グループなし。
- 開催中は初期2件と展開。終了済みは「すべて／フレンドリー／オフィシャル」で絞り込む。
- `/matches/new` で形式選択。通常は `/events/new?mode=auto|manual&group=...`、チーム戦は既存の `/team-matches/new`、公式は `/official-matches/new` を使用する。
- 通常の作成先グループはフォームで確認・変更可能。「すべて」からの作成ではグループなしが初期値。チームA/Bへ共通フィルターを強制しない。
- 保存後は既存の詳細へ直接遷移する。オフィシャル個人戦は準備中表示のみ。
- `/ranking` はサンプル数値を廃止し、グループ詳細の既存戦績タブへの入口とする。集計は追加・統合しない。
- `/profile` をマイとして使用し、グループ詳細・既存管理機能、通知、設定へのリンクを追加する。
- ハンバーガーには設定、ヘルプ、アプリについて、ログアウト、既存の通知・権限者向け管理入口を残す。テーマは設定、規約とプライバシーはアプリについてへ移す。

## 保持する処理

通常・チーム・公式の一覧はそれぞれの既存の所属範囲を使う。通常は `club_members.status` の既存条件・旧列フォールバックも維持する。チーム戦は `event_team_sides` のA/B両側を確認する。全形式を同じ権限判定へ置き換えない。一覧は500件単位でページングし、最新20件で打ち切らない。

通常の作成処理は旧ホームから `components/friendly-event-create.tsx` へ移動した。開催詳細、Round生成、固定ペア、スコア入力・保存キュー、終了・再開、プロフィール連携、戦績計算、DB定義は変更しない。通常詳細の3タブ化（PR②）は含まない。

## 下部バー・ゲスト

下部バーは認証済みのアプリ画面とゲスト利用中の試合画面で表示する。ログイン・メール確認・公開共有・規約ページには表示しない。現在位置を示し、集中操作のダイアログ中・テキスト入力中は隠す。実際のバーの高さと `safe-area-inset-bottom` を使って下余白と既存未保存警告の位置を確保する。

現在画面のスコアが保存中・失敗中の場合、下部バーの移動は止めて再試行を案内する。既存のメニュー等で他画面に移動した場合の共通保存キューと警告は維持する。ゲストの通常移動では `goTop()` や削除関数を呼ばない。マイ・ランキングはログイン案内を表示する。ゲスト用の明示的な「TOPへ戻る」、ログイン後の一時データ消去は既存仕様を維持する。

## 検証

```bash
npm test
npx tsc --noEmit --incremental false
npm run cf
```

ブラウザ試験は本番通信を遮断し、架空データで全形式の作成・詳細遷移、A/Bフィルター、グループなし、開催中2件＋展開、過去フィルター、ランキング・マイ、通知・管理者、テーマ、375/390px、ゲスト移動・明示削除、スコア取消・保存中/失敗・再試行、モーダル・未保存警告とバーの配置を確認する。

```bash
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 \
NEXT_PUBLIC_SUPABASE_ANON_KEY=local-test-key \
WRANGLER_LOG_PATH=/tmp/padel-navigation-wrangler.log npm run cf
npm run start -- --hostname 127.0.0.1 --port 3002
# 別のターミナルで実行。PlaywrightとChromiumが必要。
node tests/browser/match-navigation.cjs
```

ビルドとブラウザ試験は順番に実行する。`CHROMIUM_PATH` でブラウザの実行パス、`NAVIGATION_TEST_URL` でローカルサーバーURLを指定できる。モック用の環境変数を本番のビルド設定に登録しない。

実iPhone/Safari、本番アカウント・最新RLSを使った保存試験は含めない。本番SQL、マージ、デプロイは別途承認後に実施する。開催履歴はページング後に画面側で絞るため、将来的に非常に大量になった場合の読み込み最適化は別作業とする。
