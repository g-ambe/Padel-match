# マッチ画面のUI・UX改善

対象はPR #162を取り込んだ `7494227`。添付2件の依頼内容は同一だった。今回の変更は入力・表示・保存タイミングに限定し、試合生成・戦績・ランキング・DB構造を変更しない。

## スコア入力・自動保存

- 通常フレンドリー、手動、ゲスト、フレンドリーチーム、公式の数値入力に既存の共通 `ScoreInput` を利用する。
- 初回は片側の数字を選ぶと他方へ移り、両側を選び終えると自動保存する。片側だけ・空欄では保存しない。0も入力値として扱う。
- キーボードでは入力途中に送信せず、「完了」で保存する。数字選択ボタンの0〜12を得点上限にはしない。
- 保存済みスコアは数値を直接タップして編集する。現在値を初期表示し、片側だけの修正にも対応する。編集では「完了」まで保存せず、変更がなければ書き込まない。
- キャンセル・×・背景タップ・Escapeは入力内容を破棄して元の確定値を維持する。保存中は閉じる・再確定・数値操作を止め、保存状態を表示する。
- エラーはポップアップ内に表示し、入力を残して再試行できる。DBから成功を受け取るまで一覧の確定スコア・勝敗表示を変更しない。
- 一覧のスコア用「保存」「編集」ボタンを廃止。チーム・公式の選手情報・メモ等を編集するカードフォームの保存操作は引き続き利用できる。新規フォームでは4選手（公式は自選手2名・相手選手名2名）を設定した場合だけ、両スコアの確定時に現在のカード情報と合わせて登録する。未設定・一部入力では自動登録せず、「決定」でフォームへ反映してからカードの「保存」で明示登録する。従来許容されていた選手未設定の手動保存は維持する。
- 終了済みイベントなど、既存の編集不可条件は維持する。

通常の `getWinnerTeam`、チーム・公式の `autoResult`、各形式の入力検証・保存payload・テーブルをそのまま使用する。通常の数値条件、チーム・公式の0以上の整数、引き分け、結果の手動指定、未定の扱いは維持する。詳細スコアの自由記入欄も維持する。

## 保存失敗・二重送信対策

ポップアップ側の同期的な送信ロックと、画面側の試合IDごとのロックを併用する。通常一覧と全件モーダルのどちらから操作しても同じ画面側のロックを使用する。

通常の初回保存は従来どおり `match_results` と `matches.completed` を更新する。結果行の作成に成功し、確定に失敗した場合でも、受信した結果IDを保持して次回は同じ行を更新する。作成応答自体が失われた場合は、再試行前に保存済み結果を取得する。既に完了済みの編集では不要な確定フラグ更新を省く。

チーム・公式の新規カードには通常のUUID主キーをクライアントで発行し、再試行でも同じIDを利用する。保存済みと分かった同一IDのカードを更新するため、応答喪失後の再試行でも別カードを追加しない。新しいテーブル・カラム・RPC・制約は使用しない。更新成功と対象1行の返却を確認する。

スコア保存の成功後は画面の保存済み履歴を更新し、再取得する。再取得の失敗を保存失敗と取り違えない。`player_stats` の加減算は再導入しない。

## WIN・LOSE・DRAW

`match_results.winner_team` とチーム・公式の保存済み `result` を表示に対応させるだけで、新たに勝敗を計算しない。勝利は緑のWIN、敗北は控えめなLOSE、引き分けは中立色のDRAW。未確定・スコア未入力の試合では表示しない。

修正中・保存中・失敗時は以前の確定値の表示を維持し、成功後だけ更新する。文字と色を併用し、通常一覧と全件モーダルで同じコンポーネントを使う。WIN等の英字は今回の明示指定に従い、読み上げラベルは日本語にする。

## YouTube

全3形式で入力欄を初期状態では折りたたむ。「＋ YouTubeを追加」または「YouTube登録済み」から開き、リンク視聴・URL編集・保存・明示的な削除を行える。折りたたみでは値を消さない。未保存の入力値も画面側の状態で持つため、全件モーダルの開閉で失わない。

通常は既存のURL保存・削除関数を使う。チーム・公式は既存カードの保存payloadと検証を使用し、スコア・選手・メモ等を保持してURLを保存する。作成・メタデータ編集フォームのYouTube欄も折りたたむ。

## 一覧・全件モーダル・ゲスト

3形式とも既存のページング関数で500行ずつ取得し、取得上限で全件履歴が欠けないようにする。取得失敗時に保存成功済みの表示を消さない。通常一覧にも全試合を渡し、約3試合を目安とする高さ（最大40remまたは75dvh）で常時スクロールできる。画面が短い場合や長い選手名では見える件数が減る。通常・チームは最新から、公式は対戦相手ごとの最新から確認できる。並べ替えは表示だけで、試合番号・生成順序・データは変更しない。

「すべて表示」は同じ試合カードを使う全件履歴モーダルを開く。内部スクロール、×・背景・Escape、フォーカス復帰に対応する。内部からスコアポップアップを開いた場合は最前面だけを閉じ、スクロールロックは最後のモーダルを閉じるまで解除しない。スコア入力操作を試合のスワイプ削除へ伝播させない。

ゲストは通常の `participant_type`、チーム・公式の選手プロフィール参照とゲスト名欄から判定し、名前の横に小さな「ゲスト」タグを表示する。参加者一覧・選択肢・組み合わせ・試合カード・全件履歴で確認できる。公式の相手選手名を、根拠なく全員ゲストとして扱うことはしない。個人・グループ・ペアで異なるゲスト混在試合の集計条件は変更しない。

## ヘッダー・テーマ

スマホではイベント名と編集操作の右側にメニュー用の余白を確保し、長い名前は折り返す。375px・390pxで重ならないことを確認する。モバイルのメニュー操作領域は44px以上、PCの従来配置は維持する。

「あなた」「役職」、ゲスト、勝敗には意味別のテーマ共通カラーを使用する。ライトテーマのタグ、フォームの暗い背景、状態表示の文字色を調整し、ダークテーマも維持する。「あなた」「管理者」のタグではコントラスト比4.5以上をブラウザ上で確認する。
