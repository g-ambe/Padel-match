## 先行するアプリ変更

## 後続SQLの方針（セット07本番適用・画面確認済み）

- 所属中メンバー、グループなし開催作成者、既存スーパー管理者、チーム開催の閲覧者は維持。
- 共有は、終了済み・共有ON・未削除に加え、提示されたトークンと対象開催の一致を要求する。共有用クライアントはanonなので、ログイン状態による挙動差をなくす。
- 匿名の読取り列も共有画面が必要とする範囲へ絞る案を検証する。イベントの説明/メモ等を、画面に出ないという理由だけで非公開扱いにしない。
- 子テーブルの参照・埋込みまで、親開催の閲覧範囲に合わせる。RLS再帰とNULL/親不整合、一覧・集計の欠落を検証する。
- 2026-11-02ユーザー決定：退会後はそのグループの履歴も見せない。通常アプリの個人戦績・集計では、有効な所属がなくなったグループの過去履歴も対象外とする。過去の出場・作成者という理由だけでグループ開催の閲覧を許可する例外は追加しない。公開された共有リンク経由の閲覧は通常アプリの履歴とは別の既存要件として、提示トークンで判定する。既存のスーパー管理者権限とグループなし開催の本人閲覧は維持する。
- 既存のINSERT/UPDATE/DELETEのUSING/WITH CHECKはSELECTにも依存するため、前セットまでの正常運営を重ねて再検証する。管理者接続だけの確認で完了にしない。
- 匿名で無条件に個人プロフィールを全公開するような追加権限は入れない。公式戦official_eventsの共有は今回の6表とは別で、既存の専用グループ名RPCを維持する。
