## スコアの操作

1. チームの得点欄をタップするとポップアップを開く。
2. 上部で入力するチームを選び、0〜12の数字ボタンから選ぶ。両チームの現在の入力値は常に表示する。
3. 「キーボードで入力」で両方の得点を直接編集できる。13以上の得点も入力でき、数字ボタンの範囲を得点上限にしない。「未入力に戻す」も用意する。
4. 「決定」で画面内の入力値へ反映する。DBへの保存は既存の「保存」ボタンで行う。ポップアップの入力途中・決定時には保存しない。
5. ポップアップの「キャンセル」・×・Escape・背景タップは変更を破棄し、開く前の入力値を維持する。再び開くと現在の値を読み込む。

通常フレンドリーは従来の数値入力の条件、チーム・公式は従来の0以上の整数を使用する。空欄、0、大きな整数の扱いを維持し、不正な数値では決定できない。保存時の検証・勝敗判定・引き分け・未定・結果の手動指定・保存形式・保存先は既存コードのまま。

終了済み、または完了済みで編集操作前の通常試合は得点ボタンを無効にする。ポップアップ内の操作は通常試合のスワイプ削除へ伝播させない。ダイアログ内のスクロール、フォーカス、キャンセル後の元の欄への復帰に対応する。

「詳細スコア」はセット内訳などの自由記入欄なので、数値の得点欄へ置き換えない。戦績の閲覧画面と共有画面には入力機能を追加しない。

## 通常へ戻っていた原因と保持方法

従来の `generateRound` は生成成功後に `setRoundModeSelection({ eventId, mode: 'normal' })` を呼び、選んだ特別モードをリセットしていた。また、解放判定がfalseになった際のeffectと、生成直前の解放条件再確認でも通常へ戻していた。

生成成功時の不要なリセットを削除し、既存のReact stateで選択を保持する。スコア保存、Round表示切替、イベント終了・再開、失敗後の再試行でも選択を変更しない。実装済みの通常・バランスペア・ライバル対決の3モードと各生成器はそのまま使用する。

特別モードの解放に必要な10試合の条件は維持する。試合削除などにより条件を失った場合、選択を勝手に通常へ変えず、生成を止めて理由と必要な操作を案内する。ユーザーが通常を選ぶか、必要なスコアが再び揃うまで特別モードでは生成しない。

同じタブでの再読み込みにも対応し、明示的な選択操作のときだけ `sessionStorage` の `padel_round_mode_v1:<userId>:<eventId>` に保存する。新しいイベント・別アカウントへ選択を無条件に引き継がず、保存がなければ従来の通常モードから開始する。Storageを拒否されても画面内の操作は続けられるが、その場合の再読み込み後の保持は保証しない。

- 個人・グループ・ペア・チーム・公式の集計式、70/20/10、ゲスト混在の条件、PR #161の履歴集計方式は変更なし。
- DBテーブル・カラム・RLS・RPC・マイグレーション・既存データは変更なし。SQLの手動実行は不要。
