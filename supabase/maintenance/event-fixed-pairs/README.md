# 一部ペア固定の手動適用・検証・復旧

この変更はDraftでレビューする。本番SQL、マージ、デプロイは自動実行しない。既存のプロフィール修復やRLS改修SQLを一緒に適用しない。

## 適用の順序

1. [確認記録](preflight-review.md)と[実装・検証報告](../../../docs/event-fixed-pairs.md)を確認し、ユーザーがSQL適用を承認する。
2. SQL Editorの管理ロールで [01_preflight.sql](01_preflight.sql) を再実行する。11表のRLS、既存のID保護、eventsの一般メンバー操作ポリシー、制約・権限に変更がないことを確認する。新スキーマが既にあれば再適用しない。
3. [02_backup.sql](02_backup.sql) を手動実行する。結果の件数・日時を記録し、Supabaseの通常バックアップも確保する。バックアップは公開スキーマに置かず、同名を上書きしない。実データの出力はGitHubやチャットに貼らない。
4. [0040_event_fixed_pairs.sql](../../migrations/0040_event_fixed_pairs.sql) をファイル全体で手動適用する。既存表の列・行・ポリシー・GRANTは変更せず、3表、複合参照用インデックス、専用RPCと追加ガードを作る。前提違い・タイムアウト・失敗時はROLLBACKし、続行しない。既存Migrationは書き換えない。
5. [03_verify.sql](03_verify.sql) を手動実行する。既存定義の差分0件、不整合4項目すべて0件、3表の書込み権限なし、専用RPCの認証限定を確認する。適用直後の新3表は0件。既存イベントのstats_mode・スコアは変更されない。
6. ユーザーが結果とDraft PRを確認してから、別途マージを承認する。マージ後は既存Cloudflare自動デプロイを利用する。SQLがCloudflareデプロイで適用されるとは扱わない。
7. 安全なテスト用アカウント・グループだけで、4/5/6人、追加・解除・再読込、2端末競合、終了の未選択・記録用・通算・再開を確認する。本番の実試合に対する試験変更は禁止。

0040は末尾COMMIT。本番での試験実行として途中だけ実行しない。適用可否のリハーサルは複製DBを使う。複製DBでは末尾をROLLBACKに置き換えることでDDLと前後ガードを確認できるが、別接続の競合試験はCOMMITした隔離DBで行う。

## ローカルの試験

`npm test` に組み込みPostgreSQLの実SQL試験が含まれる。現行ポリシー・権限・ID保護を既存の適用記録から再現し、合成アカウントと合成イベントだけを作る。

同じ試験は、空の専用PostgreSQL 17を用意し、`pg` が解決できる環境で `FIXED_PAIR_PG_URL=<ローカル試験専用接続> node --test tests/event-fixed-pairs-db.test.cjs` として実行できる。この場合は2接続による設定競合・生成再試行も検査する。**既存DBや本番接続を指定しない。** 接続先にはユーザー・表・ロールを作成するため、使い捨ての隔離DBに限定する。

## 安全な復旧

- SQL適用中の失敗：同一トランザクションをROLLBACKする。バックアップを保持し、原因を修正するまでマージしない。
- リリース後の不具合：新規運営を止め、[04_disable_mutations.sql](04_disable_mutations.sql) で新しい設定・生成・終了RPCだけを無効化する。通常のスコア・動画保存は既存経路を維持する。固定を設定・利用したイベントの生成や終了は停止するため、運営者へ案内する。
- 必要なら直前の正常なCloudflare Workerへ既存の管理画面から戻し、PRのマージコミットをRevertする。今回の作業ではマージしないので、対象SHA・Worker IDは実際のリリース直前に記録する。
- **旧画面に戻すだけでは利用済みイベントの終了が拒否される。これは通算への誤反映を防ぐガードであり、旧画面のために取り外さない。** 設定・監査履歴・used_fixed_pairsは保持する。原因修正後、ユーザー承認のうえ0040末尾と同じ専用RPCの認証限定GRANTで再開する。Migration全体を再実行しない。
- 新しい表をDROPする、used_fixed_pairsをfalseへ戻す、既存行をバックアップで一括置換する操作は提供しない。新規試合がある状態で行うと、正しい履歴や反映判断を失う。必要時はバックアップと対象イベントの現状を比較し、監査・スコア・参加者IDを残す個別復旧案を作ってユーザーに承認を求める。
- バックアップ表は自動削除しない。保存期間・削除は別途承認する。
