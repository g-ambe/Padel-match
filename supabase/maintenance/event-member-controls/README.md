## DB変更は1か所

`events_operation_private.guard_member_fields()`の一般操作許可列に`name`を追加するだけ。ポリシー、GRANT、トリガー、テーブル構造、データは変更しない。既存UPDATEの所属判定とID/所属/作成者変更ガードは維持する。

apply.sqlとrollback.sqlは関数定義の完全一致・トリガー・RLS有効を確認してから、同じ関数本体を置換する。差異があれば停止する。ロック待ち3秒、SQL15秒、単一トランザクション。切り戻しは名前変更を再び管理者限定に戻し、既に保存された開催名は書き換えない。

preflight-production.jsonは本番の関数・トリガー・UPDATEポリシーのREAD ONLY取得。実行時の関数が準備SQLの期待値と一致することもREAD ONLYで確認済み。本番で試し更新や攻撃試験は行っていない。本番適用にはユーザーの明示承認が必要。
